# nanocode-machines-web

A template for a nanocode agent that pays for its own model and tools from the visitor's Tempo Wallet. It is the browser counterpart of gakonst/nanocode-machines, whose `nanocode-mpp` CLI pays per request over MPP sessions, and it serves nanocode.xyz/machines/. It is a static Vite and React app: the agent, its payments and its wallet connection all run in the visitor's browser, and no server holds keys or credentials.

- `src/agent.ts` runs the nanocode-ts build-7fab7d8 WASM module (`nanocode-ts`, `nanocode-ts/nanocode_wasm.wasm`) with an in-memory `@sqlite.org/sqlite-wasm` database, as nanocode.xyz's home page does (tempoxyz/nanocode-site `src/demo/Agent.ts`). The session is Codex `gpt-6-luna` at low effort against `https://openai.mpp.tempo.xyz/v1` with subagents enabled, and the SDK's `dispatch` sends each model request through the payment client unchanged.
- `src/machines.ts` holds the instructions, the suggested prompts and the one host tool, `pay`. It sends a batch of requests at once and only to `https://<name>.mpp.tempo.xyz` origins, so the agent cannot spend the visitor's MACH anywhere else. Its instructions list the services and request shapes of the nanocode-mpp storm recording: rpc, openrouter, kicksdb, storage, firecrawl, Microsoft and ElevenLabs speech, fal and goflightlabs. It returns each response's status, type, time and at most 1,000 characters of its body, because the visitor pays for every token the model reads back.
- Tempo's MPP proxies allow browsers. On 2026-10-21 each `*.mpp.tempo.xyz` origin the tool uses answered a preflight from https://nanocode.xyz with `access-control-allow-origin: *`, allowed `authorization`, `content-type`, `payment-session` and `accept-payment`, and exposed `WWW-Authenticate` and `Payment-Receipt`. https://rpc.tempo.xyz allows any origin too. https://mpp.dev/api/services sends no CORS headers, so the service list lives in the instructions.
- `src/wallet.ts` connects Tempo Wallet with the Tempo Accounts SDK (`accounts` 0.21.0, `tempoWallet` with `Mount.popup()`). The page generates a secp256k1 access key and asks `wallet_connect` to authorize it (`authorizeAccessKey`), as tempoxyz/xframes builds its services keys (`servicesPolicy` and `keyRequest` in its `src/tempo.ts`), with MACH only:
  - a limit of `allowance` (2 MACH) and an expiry a day out;
  - scopes for MACH `transferWithMemo`, MACH `approve` to the swapper and the swapper's `swapTo` (machine-token charges), and the TIP-1034 escrow's `open`, `topUp`, `requestClose` and `withdraw`.

  The key, its account and the returned `keyAuthorization` stay in localStorage under `nanocode.machines.wallet` until the key expires or the visitor forgets it, so a script on the page could spend at most what is left of the allowance. `signer` seeds viem's `KeyAuthorizationManager` with the authorization, so the key's first transaction carries it on chain. Tempo Wallet's MACH checkout opens with `Mach.fund`.
- `src/payments.ts` pays with mppx 0.13.6, xframes' version. It ranks challenges as xframes' `payer` does: MACH sessions first, then machine-token charges, then MACH charges. Channels live in localStorage per key, so a reload reuses them.
  - The proxies send no `suggestedDeposit`, so mppx would open each channel with one request's price: on 2026-10-21 the first Luna request's open asked for 289 atomics. Every request therefore passes `context.depositRaw` for a 0.05 MACH opening deposit. Top-ups are also 0.05 MACH, and `maxDeposit` caps a channel at 0.5 MACH.
  - Deposits count against the key's limit. Nothing in the page closes channels.
- `src/Spend.tsx` is the spend panel of the nanocode-mpp TUI. Its title reads `⚡ <total> MACH streamed · <n> paid calls · <n> services · <rate> MACH/min`. Each service has a row with a live `●`, a 30-second sparkline, its spend and its call count. `payments.ts` takes spend from receipts:
  - session receipts come from `Payment-Receipt` headers and from the `payment-receipt` events of metered streams, which it reads as the stream passes through unchanged. Each is charged as the rise in its channel's cumulative `spent` since the last receipt this browser saw, which is kept in localStorage;
  - charges are taken from their challenge's amount on mppx's `payment.response` event.
- The page copies nanocode.xyz's design: `src/style.css` is gakonst/nanocode-vercel-durable's `app/globals.css`, and `src/Reply.tsx`, `src/fences.ts`, `src/highlight.ts` and `src/theme.ts` are its reply and code-highlighting files. `index.html` carries nanocode.xyz's numbered navigation with absolute links and this demo current, so copy navigation changes here as nanocode-vercel-durable and nanocode-cloudflare-durable do. Its Open Graph card is https://nanocode.xyz/og/machines.png, which tempoxyz/nanocode-site renders from its `Head.demos`. `Reply` renders Markdown images, which fal's results become.
- `npm run deploy` builds and deploys `nanocode-machines-web`, a Worker that serves only static assets. Production runs in Cloudflare's Tempo Development Resources account (`CLOUDFLARE_ACCOUNT_ID=0a39052b0a32ba8c8444345fe21b7595`), at https://nanocode-machines-web.tempo-dev.workers.dev. tempoxyz/nanocode-site's Worker serves it at https://nanocode.xyz/machines/ through a service binding with the prefix removed. Vite builds with `base: "./"`, so every URL is relative and the same build works at either address.
- Checked on 2026-10-21 without spending:

The agent's first model request reached the OpenAI proxy's 402, and mppx chose the MACH session and built the channel open. The open's gas estimate reverted with `InsufficientBalance`, which the page reports as too little MACH.
  - Connect opened Tempo Wallet's popup with the access-key request.
